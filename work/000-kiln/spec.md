# Task 000-kiln: Specification

Derived from: `work/000-kiln/intent.md`

## 1. System Overview
**Kiln OS** is a portable, resilient, token-minimizing operating system for AI coding agents. It enforces software engineering discipline via git-backed artifacts, deterministic CLI hooks, a 5-tier dual-graph memory architecture, and a strict token governor.

---

## 2. Architecture & Data Models

### 2.1 Knowledge Graph (Graph B - Authoritative & Git-Native)
- **Node Storage**: `.kiln/graph/nodes/<id>.md`
- **Node Schema (YAML Frontmatter)**:
  ```yaml
  id: string              # e.g., "dec-001", "req-002", "std-python"
  type: string            # intent | requirement | spec | decision | standard | module | test | lesson | incident | release
  title: string           # Short descriptive title (<=10 words)
  status: string          # proposed | accepted | superseded | stale
  confidence: float       # 0.0 to 1.0
  created: ISO8601 string # e.g. "2026-09-28T16:00:00Z"
  source: string          # author / agent / commit / url
  evidence:               # files or commits validating this node
    - file: string
      sha256: string
  valid_from: ISO8601 string # start of assertion validity
  valid_to: ISO8601 string   # null if currently valid
  supersedes: string         # id of node superseded by this node (if any)
  edges:
    - target: string         # target node id
      type: string           # derives_from | satisfies | constrains | verified_by | touches | supersedes | caused_by | learned_from
      valid_from: ISO8601 string
      valid_to: ISO8601 string
  ```
- **Event Log**: `.kiln/graph/events.jsonl` (Append-only)
  ```json
  {"timestamp": "2026-09-28T16:00:00Z", "event": "node_created", "node_id": "dec-001", "actor": "agent", "payload": {...}}
  ```
- **Compiled Index**: `.kiln/graph/index.db` (SQLite, derived, rebuildable, gitignored)
  - Tables:
    - `nodes(id PRIMARY KEY, type, title, status, confidence, created, valid_from, valid_to, supersedes, body_summary, token_count)`
    - `edges(source_id, target_id, type, valid_from, valid_to, PRIMARY KEY(source_id, target_id, type))`
    - `evidence(node_id, file_path, sha256)`
    - `fts_nodes USING fts5(id, title, body_summary)`

### 2.2 Code Graph (Graph A - Disposable AST)
- Maps symbols, function calls, endpoints, and test coverage using Tree-sitter MCP or lightweight local AST parser.
- Disposable and rebuildable.
- Bridge edges connect Knowledge Graph to Code Graph (`requirement -> symbol/file`, `decision -> module`).
- **Invariant**: Code Graph is used only for navigation; the agent **must always** read the raw target file before editing.

### 2.3 Five-Tier Memory Hierarchy
1. **L0 Hot (`<=300` tokens)**: Byte-stable `AGENTS.md` + active task session state checkpoint (`work/<id>/state.yml`).
2. **L1 Working**: Active task context pack generated by `kiln pack <work-id> --budget N`.
3. **L2 Warm**: Graph index overview (ID, type, title, one-line summary, token cost).
4. **L3 Cold**: Full markdown node bodies, ADRs, historical requirements (fetched via `kiln node <id>`).
5. **L4 Raw**: Git commits, raw CLI logs, transcripts (streamed/grep only).

### 2.4 Retrieval Algorithm (`kiln pack`)
Deterministic, non-LLM algorithm:
1. Identify seed nodes: current task ID (`work/<id>`) + files touched in current git diff.
2. Traverse graph via Personalized PageRank / Decayed BFS (damping factor 0.85, depth <= 3).
3. Filter out nodes where `status == 'superseded'` or `valid_to < now` (unless specifically inspecting history).
4. Score nodes:
   $$\text{Score} = \frac{\text{Relevance} \times \text{Recency} \times \text{Confidence} \times \text{StatusWeight}}{\text{TokenCost}}$$
5. Pack highest scoring summaries until budget $N$ is reached.

## 3. Token Governor Specification

1. **Context & Caching**:
   - `AGENTS.md` strictly limited to $\le 80$ lines.
   - Pointers over copies: inject node IDs and 1-line summaries; expand via `kiln node <id>` only when needed.
   - Inject at most 5 standards via `standards/index.yml` matching task domain.
2. **Lean-Build & Terse Rules**:
   - Terse output applied exclusively to agent conversational prose and intermediate thoughts.
   - Explicit prohibition: Never compress specs, plans, security warnings, test outputs, or diffs.
3. **CLI Output Filtering**:
   - Filter noisy compiler and test output (e.g. collapse repetitive passing lines, retain full stack traces on failure).
4. **Budgets & Linter (`kiln lint-tokens`)**:
   - CI validation fails if:
     - `AGENTS.md` > 80 lines.
     - Skill description > 40 words.
     - Template file > 40 lines.
     - L0 snapshot > 300 tokens.

## 4. Lifecycle & Rigor Tiers

### 4.1 Lifecycle Stages
`Discover` $\to$ `Requirements` $\to$ `Design` $\to$ `Plan` $\to$ `Build` (TDD) $\to$ `Test` $\to$ `Review` $\to$ `Docs` $\to$ `CI/CD` $\to$ `Release` $\to$ `Observe` $\to$ `Incident` $\to$ `Maintain` $\to$ `Learn`

### 4.2 Rigor Tiers
- **Spark (Tier 0)**: Zero checkpoints, fully automated execution for small fixes.
- **Standard (Tier 1)**: 1 design/plan approval checkpoint, automated TDD gate, committed artifact chain.
- **Critical (Tier 2)**: 2 checkpoints (Plan + Pre-merge Review), human diff approval, strict rollback rehearsal.

### 4.3 Stage Artifacts
Stored in `work/<id>/`:
- `intent.md`: High-level goal, tier classification, scope boundaries.
- `spec.md`: Architectural details, schemas, interfaces, invariants.
- `plan.md`: Step-by-step verified tasks with runnable commands.
- `state.yml`: Machine-readable stage tracker, active checkpoints, token spend.
- `review.md`: Automated check output, test logs, security audit.

---

## 5. Resilience & Prompt-Injection Defenses

1. **Rebuildability**: If `.kiln/graph/index.db` is deleted or corrupted, `kiln doctor` rebuilds it from `.kiln/graph/nodes/*.md` and `events.jsonl` with bit-for-bit query parity.
2. **Degradation**: If graph tooling or MCP is offline, CLI degrades to direct file reading and grep.
3. **Prompt Injection Quarantine**: Graph memory content and tool outputs are tagged as untrusted data (`<kiln-untrusted-data>...</kiln-untrusted-data>`). Execution of instructions embedded within memory nodes is explicitly barred.
4. **Deterministic Hook Gates**:
   - Safety gates (fail closed): protected branch pushes, secret leaks (`.env`, private keys), tests-not-edited checks, production deployment gates.
   - Helper hooks (fail open): formatting, linting warnings, cache warmup.

## 6. CLI Command Interfaces (`scripts/kiln` or `kiln`)

- `kiln init`: Initializes `.kiln/` directory, templates, standards, and git hooks.
- `kiln pack <work-id> [--budget N]`: Generates L1 context pack for active task.
- `kiln node <id>`: Fetches and displays full L3 markdown node.
- `kiln remember --type <type> --title <title> [--edges ...]`: Adds knowledge node with schema validation and secret redaction.
- `kiln doctor`: Audits graph integrity, orphan edges, stale nodes, schema violations, and rebuilds index if missing.
- `kiln resume <work-id>`: Restores task session from `work/<id>/state.yml` without repo re-reading.
- `kiln build-adapters`: Generates harness-specific files (`CLAUDE.md`, `.agent/skills/`, etc.) from `.kiln/`.
- `kiln lint-tokens`: Checks token budget limits on templates, skills, and instructions.
